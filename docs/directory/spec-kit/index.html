Spec Kit: GitHub's toolkit for spec-driven agent work

CURSORCLAUDE CODECODEXANY STACK

By GitHub · License: MIT

Spec Kit is a process installer. It gives an agent a spec, a plan and a place to record outcomes, then wires that process into Cursor, Claude Code, Copilot, Codex and a long list of other tools.

Open Spec Kit

What it does

You install the CLI with uv tool install specify-cli (Python 3.11+ and uv) and run specify init with an integration key for your agent. That writes skills or commands such as /speckit-* into the tool's directory.

Built-in processes include spec-driven development, plus extensions for bug fixing and idea assessment. The project also documents presets, workflows, catalogs and air-gapped installs. Community catalog entries are not audits; the README says to review source before you run it.

This is GitHub-published and MIT licensed. It is not "GitHub Copilot only." The integrations table is long and will change.

Who it is for

Teams that want the agent to write a spec before code, especially on greenfield work or on a change that will outlive one chat. Also orgs that want a repeatable process across several coding tools.

Heavy for a typo fix. If your problem is "the agent disabled RLS," a glob-scoped rule is faster than a spec ritual.

Our take

Shipping a real CLI with agent integrations is more serious than a blog-post methodology. The split between SDD, bugfix and assessment is clearer than most "just use agents" kits.

Limits: you inherit Spec Kit's vocabulary and file layout. Agents can still produce a beautiful spec and wrong code. Catalog installs are a supply chain. The tool will not encode your Stripe or Godot conventions.

We did not run every integration. Check the docs for your agent before you promise it to a team.
