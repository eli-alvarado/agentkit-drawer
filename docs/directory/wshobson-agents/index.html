wshobson/agents: one marketplace aimed at several coding tools

CLAUDE CODECURSORCODEXPYTHONANY STACK

By wshobson · License: MIT

Most collections pick one tool. This one tries to be a shared source that each harness installs differently: marketplace for Claude Code and Cursor, generated artifacts for Copilot, OpenCode and others.

Open wshobson/agents

What it does

The README describes a large catalog of plugins built from shared Markdown, plus agents, skills and commands. Claude Code setup is /plugin marketplace add wshobson/agents then install a named plugin such as python-development@claude-code-workflows. Other tools have make install-* routes.

Coverage includes Python and JavaScript development, review, testing, infrastructure and security. There is a capability matrix because not every harness supports hooks or MCP the same way.

The size is the product. You are not adopting one workflow; you are opening a store.

Who it is for

Teams that already standardized on several coding agents and want the same specialist prompts in each. Also Python folks who want a FastAPI-oriented plugin without writing the agent file.

Skip it if you are still writing your first AGENTS.md. A 90-plugin catalog will hide the ten lines you actually need.

Our take

Multi-harness packaging is the interesting idea. If you live in Claude Code on Monday and Codex on Tuesday, a shared source beats maintaining two trees.

The limit is cognitive load and surprise behavior. Generated adapters can drift from the Markdown. Plugins may register hooks or MCP you did not notice. Install one plugin, read what landed on disk, then decide.

We did not count the catalog ourselves for this page and we will not quote the README's totals as if we audited them.
